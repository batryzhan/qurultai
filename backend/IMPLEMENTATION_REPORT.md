# Backend implementation report

Implemented: FastAPI API matching docs/IMPLEMENTATION.md; strict Pydantic request validation; SQLAlchemy SQLite persistence; Alembic migration automatically applied on startup; persisted SSE event replay with Last-Event-ID; independent parallel role analyses, prior-context cross examination, revision and synthesis; incremental argument persistence; JSON dataset imports; persisted single/majority/debate runs; normalized exact-match accuracy, Brier score and 10-bin ECE; JSON/CSV export; deterministic explicitly simulated provider; server-side Alem adapter with configurable model IDs and required validated JSON answers. Source corpus contains two real, short primary-source abstract excerpts checked on 2026-10-19. Retrieval is lexical and marked retrieved_unverified; no automatic source-to-claim verification is claimed. Different concise answers create an answer_difference record linked to stored initial arguments, not an invented semantic contradiction.

Security/resource controls: root .env loaded without overriding environment; secrets server-side; safe provider error messages; HTTPS endpoints without URL credentials/query required; configured CORS origins; 1MB request-body cap; input/schema limits; at most two active jobs per server process; at most three concurrent live provider requests; at most forty calls per council; one repetition; live benchmark cap twenty questions; bounded timeout; max_tokens 1200 request parameter (provider support unverified); spreadsheet formula injection neutralized in CSV. No automatic retry multiplies cost. Running work is marked failed after restart with partial output retained and terminal SSE event. This is a local single-worker application, not a multi-worker distributed queue.

Tests cover completed demo session, SSE replay, JSON/CSV exports, all three benchmark strategies, known numerical calibration cases, majority ties, source/conflict honesty, provider HTTP/malformed/timeout/valid-usage paths via httpx.MockTransport, endpoint/model config fallback, unsafe endpoint redaction, input validation, persistence, live missing-config failure, duplicate-start rejection, independent initial context, prior response cross examination, and restart failure events. Ruff passes after formatting/fixes; final check logged separately by parent if repeated.

Limitations: actual Alem credentials/model capabilities not verified. Adapter assumes basic Chat Completions; prompts request JSON rather than assuming response_format support. Missing usage stays null; debate total sums each distinct response and synthesis only when all usage exists. No token estimates or monetary costs are invented. Majority confidence is null because no principled aggregation calibration is established. Demo answers are deterministic placeholders; only explicit 2+2 examples answer 4. Benchmark ground truth is never passed to providers. Dataset verified is a user assertion, not independent certification. No CSV dataset import, arbitrary file upload, web search, semantic claim extraction, automatic source entailment checks, retry/resume, statistical significance inference, or benchmark chart API aggregation is implemented. Database uses JSON aggregate records plus relational indexed event log rather than fully normalized per-argument tables; suitable for local prototype, not high-volume research storage. Session/dataset history currently returns full lists without pagination. Public response payloads are contract-shaped dictionaries; inputs are strict Pydantic schemas. No authentication, deployment, official empirical comparison, or research result is claimed.

Run from repository root: `.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000`. Startup automatically migrates DB. Run tests: `.venv/Scripts/python.exe -m pytest backend/tests -q`. Manual migration from backend working directory: `../.venv/Scripts/python.exe -m alembic upgrade head`. Dependency ranges are in backend/pyproject.toml; parent can freeze the tested environment for reproducibility.

## Prompt protocol follow-up (2026-10-19)

Upgraded to council-v2. Each stage now has operational instructions: independent analysis forbids peer assumptions; cross examination must address identified peer claims with supported agreements/challenges and avoid manufactured disagreement; revision reports changed conclusions and uncertainties; synthesis preserves stored disagreement positions, distinguishes new propositions, and cites only supplied source IDs/URLs without asserting verified entailment. Synthesis now receives persisted disagreement records in addition to argument/evidence context. Self-reported confidence is explicitly uncalibrated. Configuration guidance explains the shared ALEM_MODEL fallback.

Each benchmark configuration now freezes a deep-copied prompt_snapshot containing the exact shared system format template, role texts, all stage directives, user payload template, version, and SHA-256 of canonical sorted UTF-8 JSON before adding its hash. Later runtime dictionary changes do not mutate this saved snapshot. Existing runs retain their saved original metadata; new runs identify council-v2. No external provider capabilities were assumed or verified by this change.

Implemented protocol change, then all 16 backend tests passed in root .venv (2.18 seconds) with the same dependency deprecation warning; Ruff check/fix and format completed successfully.
